# 하디 상세페이지 제작

상품 URL·이미지 → 사용자의 **하디 무한상세페이지 프롬포트** GPT → TYPE 선택·최종 원고 → 실제 Figma 템플릿 작업 사본 → 최종 4종을 제작한다. 원고 생성부터 Codex가 담당한다.

## 작업본과 실행 환경

- 저장소의 `.agents/skills/detail-page-production/`에서 로드했다면 세 단계 상위가 루트다. 사용자 스킬 폴더에 설치됐다면 옆 `repo-location.json`의 `repository_root`를 읽는다. 경로가 사라졌으면 현재 열린 작업본을 확인하고 없으면 지정 GitHub 저장소를 새 폴더로 복제하여 설치기를 다시 실행한다.
- 루트 `AGENTS.md`, `config/workflow.json`, `config/hadi-four-set.json`을 읽는다. 첫 PC 설치는 `docs/new-pc-setup.md`를 따른다. 실행 경로는 해당 PC의 `.local/runtime.json` 또는 실제 사용 가능한 도구에서 확인한다.
- 최초 정적 작업은 사용 가능한 Python으로 `scripts/setup_portability.py --repo <루트>`를 실행해 `.local/machine.json`과 연결 초안을 준비한다. 기존 설정은 보존한다.
- 브라우저는 Aside 스킬과 현재 연결 프로필을 먼저 확인한다. 실제 Figma 편집은 연결된 플러그인과 Figma 스킬을 사용한다. 기본 정적 제작에 Flow·Remotion 설치는 필요하지 않다.
- 설치 검사와 실제 하디 GPT·이미지 도구·Figma 연결은 별도 검증한다. 인증·권한·도구가 실제 막힌 항목을 알리고 진행 가능한 나머지를 수행한다.

## 1. 상품 입력과 사실 수집

`jobs/<날짜>-<pc-id>-<상품>/`에 원본 이미지·URL·판매자 정정·출처를 보존한다. URL만 받았으면 상품 페이지와 상세이미지를 열어 실제 사진과 옵션을 확보한다. URL 접근이 막히고 사진도 없을 때만 자료를 요청한다. 옵션별 URL은 사용자 요청에 맞춰 같은 상세페이지로 묶는다.

브랜드는 와이홉/유앤채 중 판매 정보와 기존 지정을 따른다. 모호하면 물어본다. 소재·혼용률·판매 색상은 최신 판매자 정정이 우선한다. 상품 사진의 형태·배색·짜임·부품을 기준으로 만든다. 미확인 치수는 소비자용 결과에서 행을 생략한다. FREE가 확인되면 FREE로 쓴다. '실측 미제공', '업체 미제공' 같은 내부 부족 사유를 라벨·상세페이지에 쓰지 않는다. 다른 제품의 소재나 수치를 가져오지 않는다.

## 2. 실제 하디 GPT에서 원고 수령

`docs/hadi-prompt-intake.md`를 읽는다. `.local/connections.json`의 `hadi.gpt_url` 또는 로그인된 ChatGPT의 고정 GPT **하디 무한상세페이지 프롬포트** 항목을 사용한다. 제목·제작자 안내·입력 흐름을 확인한다. 현재 UI는 GPT 선택 후에도 루트 URL일 수 있어 URL만으로 판단하지 않는다. 서비스 이전 안내가 있으면 현재 GPT 또는 후속 플러그인 연결 상태를 확인한다. 공개 GPT 식별자만 공통 설정에 넣을 수 있고 대화·프로필·계정·세션 식별자는 PC 로컬에 둔다.

1. 해당 GPT에 이번 상품의 새 대화를 시작한다. 기존 다른 상품 자료를 섞지 않는다.
2. 상품 사진과 확인된 판매 정보를 제공한다. URL만 붙여 넣고 이미지 분석됐다고 판단하지 않는다. 실제 첨부와 업로드 완료를 확인한다.
3. 자료 제공이 끝나면 GPT 안내의 완료 신호 '끝'을 보낸다. 응답 완료를 관찰하고 TYPE1~7 비교·추천을 읽는다.
4. 지정 TYPE을 우선 선택한다. 미지정이면 제품 적합성과 GPT 추천으로 선택해 근거를 기록하고 제작을 계속한다.
5. 최종 원고 전체를 `prompt/hadi-final.md`에 저장한다. 실제 GPT 주소·제출 자료·비교표·TYPE 선택 근거·응답 출처를 `prompt/intake.json`에 기록한다. 응답이 끊기면 같은 대화에서 이어 받아 전체 항목을 확보한다.

실제 응답을 확보해야 이 단계가 완료다. 연결이 막히면 그 상태를 알리고 입력 수집·사실 검증을 계속한다. 로컬 창작 원고는 사용자가 대체 작성을 허용했을 때만 만들고 출처를 구분한다.

## 3. 템플릿과 이미지 제작

`docs/template-map.md`, `config/template-structure.json`과 live Figma에서 선택 TYPE의 **실제 번호·프레임·복수 이미지 슬롯**을 확인한다. `config/studio-portability.json`의 사용자 소유 마스터를 보존하고 상품별 사본을 만든다. 공유 원본의 권한을 바꾸지 않는다. TYPE6의 3~18 번호를 모든 TYPE에 강제하지 않는다.

원고를 실제 슬롯에 매핑한다. 예시 브랜드·수치·소재·보장, 미확인 사은품·후기는 제외하고 사실에 맞게 카피를 조정하여 원문과 변경 근거를 남긴다. 기본 패키지의 리드 영역은 고품질 정적 화보·제품 이미지로 만든다. 영상은 사용자가 요청할 때 `docs/production-workflow.md`와 영상 실행서를 추가 적용한다.

대표이미지는 기본 **흰색 바탕에 판매 제품만** 보이게 하고, 실제 형태·배색·구성을 맞춘다. 필요한 옵션별로 제작한다. 모델·연출 배경·장식·임의 문구를 대표이미지에 추가하지 않는다.

착용 화보는 `config/models.json`, `docs/fixed-models.md`의 승인 F01/M01 기준 얼굴과 필요한 시트·원본 제품을 실제 이미지 도구에 첨부한다. 의상·헤어·표정은 계절·제품·타깃에 맞게 현대적으로 연출하며 의상 색도 제품과 조화시킨다. 제품이 잘 보이고 신체·관절·실착 크기가 자연스러워야 한다. 양말의 부츠 착용 준비컷처럼 상황에 맞는 장소와 자세를 고른다. 한 상품의 옷 색·포즈·혼용률을 다른 상품 규칙으로 고정하지 않는다.

내장 이미지 도구를 우선 사용하고 실제 확인 가능한 모델·화질을 기록한다. 별도 유료 API 전환·크레딧 구매는 자동 실행하지 않는다.

## 4. 실제 Figma와 최종 4종

실제 Figma 플러그인으로 템플릿 작업 사본에 이미지와 원고를 교체한다. 브랜드·소구 카피·Q&A·옵션·사양·제품정보는 편집 가능한 텍스트와 표로 만든다. 템플릿의 타이포·강조·구조를 살린다. 로컬 새 레이아웃이나 빈 사본을 Figma 완성본으로 대신하지 않는다.

제품정보는 **상세페이지 안에도 포함**하고 **같은 프레임을 별도 라벨 PNG로 추가 출력**한다. 정정 시 두 결과를 함께 갱신한다. 제품정보 글자를 이미지 모델에 생성시키지 않는다.

1. `representative*.png` — 흰색 배경 제품 단독 대표이미지, 필요한 옵션별.
2. 편집 가능한 실제 Figma 디자인 링크 — 작업 사본의 정확한 file key와 node ID. 로컬 .fig를 별도 요청하면 실제 내보내기까지 수행한다.
3. `detail-page.png` — 완성한 Figma 프레임에서 내보낸 전체 상세페이지 PNG, 템플릿 폭 기준.
4. `product-information.png` — 상세페이지 제품정보 프레임에서 별도 내보낸 PNG.

전체 슬롯·예시 잔존·제품 배색·고정 얼굴·신체·글자 잘림·사양을 실제 검수한다. 대표이미지, Figma 편집 구조, 전체 PNG와 라벨을 각각 열어 확인한다. `docs/hadi-four-set-workflow.md`에 따라 manifest와 QA 근거를 저장하고 `scripts/static_delivery.py`로 파일·해시·PNG·Figma 경로·증빙을 검사한다. 검증 스크립트만으로 live 편집·시각 품질을 통과시키지 않는다.

## 역할과 재시작

`.codex/agents/detail_production_coordinator.toml`을 총괄 역할로 사용한다. 독립 작업은 이미지 감독과 Figma 조립 역할에 파일·슬롯 소유권을 나눠 맡긴다. 하나의 Figma 사본과 하나의 하디 GPT 제출은 각각 한 담당자만 쓴다. 역할 설정을 로드하지 못하는 클라이언트는 같은 지침을 기본 하위 에이전트에 전달하거나 순차 실행하고 실제 방식을 보고한다.

원고·제출 자료·생성 이미지·Figma 노드·출력 해시·검수를 작업 폴더에 저장한다. 재개 시 실제 기존 결과를 확인해 재사용한다. final에는 4종 실제 링크, 선택 TYPE, 필요한 제한을 간결하게 알린다. 실제 쿠팡 등록은 별도 요청 범위다.
