# Cupang Detail Image Studio

와이홉·유앤채 상세페이지를 개인 PC의 Codex로 제작하는 작업실입니다.

**사용자가 하디 채팅의 1~4단계를 마치고 브랜드·TYPE·영상 자막 모드를 지정하면, Codex가 전체 상세 이미지·리드 영상 2개·Figma 상세페이지 조립·검수·출력을 진행하는 제작 워크프로세스입니다.** 개인 PC의 Codex와 연결된 제작 도구를 사용합니다.

## 시작

이 저장소를 Codex 프로젝트로 열고 다음처럼 요청합니다.

> 이 저장소의 워크프로세스로 전체 제작 시작. 브랜드는 와이홉, TYPE6, 영상은 자막 있게. 승인된 여자·남자 얼굴과 캐릭터/표정 시트를 참조하고 의상·헤어스타일은 제품에 맞게 바꿔줘. 아래는 하디에서 받은 최종 프롬프트이고, 첨부한 사진이 원본 제품 사진이야. 3~18의 필요한 이미지와 카피, 리드 영상 2개, 편집 가능한 Figma 상세페이지를 완성하고 영상은 각각 다운로드하게 해줘.

Codex는 `AGENTS.md`와 프로젝트 스킬을 읽고 사진·원고를 저장해 작업을 진행합니다. 사용자가 별도로 JSON을 쓰거나 이미지·영상·문구를 수동 배치하는 방식이 아닙니다. 이전 작업은 작업 ID로 이어서 실행합니다.

영상은 **자막 있음 / 자막 없음**으로 선택합니다. 자막 있음은 Gmarket Sans Bold 모션 타이포, 자막 없음은 글자와 자막 띠가 없는 영상입니다. 같은 원본을 로컬에서 편집하므로 선택을 바꿀 때 Flow를 다시 생성하지 않습니다. 선택을 생략하면 기존 호환을 위해 자막 있음으로 저장합니다.

착용 컷은 승인한 F01 여자 얼굴과 확정한 M01 남자 사진을 기준으로 만듭니다. 각 모델의 **정면·왼쪽·오른쪽·뒷모습·표정 캐릭터 시트와 추가 화보 표정 시트**를 보조 참조로 등록하고 실제 기준 얼굴·필요한 시트·원본 제품 사진을 함께 사용합니다. **얼굴은 유지하고 의상·헤어스타일은 제품·계절·화보 콘셉트마다 스타일리시하게 변경**합니다. 몽환적인 화보 참고 사진은 표정·시선·빛의 분위기에만 사용합니다. 시트는 광고에 그대로 넣는 이미지가 아니라 각도·표정의 일관성을 위한 제작 참조이며 시트의 의상·헤어스타일을 매 작업에 고정하지 않습니다. 같은 연속 장면에서는 의상·헤어스타일을 유지합니다. [고정 모델 규칙](docs/fixed-models.md)을 따릅니다.

공식 Remotion Agent Skills 12개와 로컬 렌더러 4.0.533을 설치했습니다. 자막 있음·없음 두 모드의 실제 5초 MP4 렌더를 시험했습니다. [로컬 Remotion 실행서](docs/remotion-local.md)를 참조합니다.

## 고정 워크프로세스

1. 사용자가 **하디 채팅 시작 → 제품 사진 제공 → TYPE 선택 → 최종 프롬프트 수령**까지 진행하고 브랜드·영상 자막 모드를 지정합니다.
2. Codex가 원고와 원본 제품 사진을 보존하고, 고정 얼굴·캐릭터/표정 시트 참조를 결속하며 선택 타입의 실제 슬롯에 제작 계획을 연결합니다. 의상·헤어스타일·화보 표정은 제품과 콘셉트에 맞춰 설계합니다.
3. 원고의 나머지 항목에 필요한 AI 이미지를 모두 제작합니다. 현재 TYPE6의 **3~18**은 브랜드 화보·제품 랜딩·활용도·POINT·사용법·디테일·실제 색상 이미지와 편집 가능한 카피·사양으로 구성합니다. 다른 TYPE은 각자의 구조와 복수 이미지 슬롯 수를 따릅니다.
4. 리드1·리드2를 각각 5장면 스토리보드로 기획하고 **Flow 생성 한 번씩, 출력 x1**로 원본 영상 두 개를 만듭니다.
5. 원본의 검수 구간을 각 5초로 로컬 편집한 뒤 Remotion으로 자막 있음/없음 선택을 적용합니다. 자막 있음은 Gmarket Sans Bold 포인트 모션 타이포입니다.
6. 사용자 소유 템플릿의 작업 사본에 모든 필요한 정적 이미지·카피·브랜드·사양과 리드 MP4 두 개를 배치합니다.
7. 제품·고정 얼굴·레이아웃·카피·영상 재생을 실제 검수하고 **완성된 편집 가능한 Figma 링크, 리드1 MP4 다운로드, 리드2 MP4 다운로드** 및 순서별 정적 이미지·미리보기를 제공합니다.

사진이나 판매자가 확인하지 않은 치수·소재·효능을 만들지 않습니다. 없는 사은품·후기 모듈은 제외하고 이유를 기록합니다. 워크프로세스 설정이나 캐릭터 시트·리드 샘플만 요청한 작업은 전체 상세페이지 제작 완료로 표시하지 않습니다.

## 새 작업의 기본값

Flow는 **리드당 생성 한 번·출력 x1**입니다. 5개 장면을 한 스토리보드로 요청하고 5초가 미지원이면 지원 길이로 원본 하나를 만든 뒤 로컬에서 최종 5초로 편집합니다. 제출 전에 UI의 모델·길이·x1·표시 비용을 기록하고 단일 요청을 예약합니다. 재시작하거나 결과가 불명확해도 다섯 장면을 따로 생성하지 않습니다.

착용 화보·제품 회전·디테일과 줌·슬로 연출을 중심으로 구성합니다. 자막 있음은 **Gmarket Sans Bold 타이포를 화면을 채운 영상 위에 얹으며 검은 하단 자막바는 사용하지 않습니다.** 자막 없음은 텍스트 모션까지 생략합니다. 승인된 편집 카피와 사유를 job에 기록하고 원문도 별도 보존합니다. 최종 납품에는 완성된 편집 가능한 Figma 결과와 직접 다운로드할 **리드별 MP4 두 개**가 포함됩니다.

`studio.py plan`의 새 기본은 `single-source-v2`이고 자막 있음 샘플은 원본·표시 자막·최종 영상, 리드당 세 산출물, 자막 없음은 원본·최종 영상, 리드당 두 산출물을 추적합니다. 기존 `legacy-five-source-v1` 계획과 QA는 그대로 재개하며 새 v2 폴더로 자동 변환하지 않습니다. [v2 편집 절차](docs/fullbleed-v2.md)와 [상태·생성 예약 명령](docs/job-format.md)을 참조합니다.

## 들어 있는 것

- 원고 분리, 작업 검증, 생성 계획, 초별 자막, 재개 상태 관리 도구
- 5개 구간을 정확히 5초로 조립하는 영상 편집 도구
- 리드 2개 샘플 검증과 전체 제작 재개를 분리하는 실행 범위
- live Figma 검사·복제·텍스트 수정용 실행 코드 생성기
- Codex 프로젝트 스킬과 작업 시작 지침
- 승인된 F01/M01 얼굴·캐릭터/표정 시트 참조와 의상·헤어스타일 변경 규칙

## 현재 검증 범위

로컬 템플릿의 3,295개 노드와 TYPE1~7 구조를 해석하고, 사용자 계정에 마스터 사본을 가져와 실제 Figma 도구에서 전체 타입 연결을 확인했습니다. **이전 v1 실물 TYPE6 리드 샘플**에서는 이미지 생성 → Flow 소재 생성 → 리드별 5초 편집·한글 자막 → Figma MP4 삽입까지 실행했습니다. Figma의 네이티브 **File → Place image/video**로 넣은 두 영상은 프로토타입의 실제 영상 DOM과 화면으로 재생을 확인했습니다. v1 최종 MP4는 768×500·30fps·150프레임입니다. 이 기록은 새 디자인 통과를 의미하지 않습니다.

검증 범위는 **리드메시지 1·2 샘플**입니다. 샘플 QA가 모두 통과한 상태는 `sample_verified`이며 `page_complete:false`입니다. 전체 상세페이지 제작·납품은 아직 실물 작업으로 검증하지 않았습니다. v2 단일 원본 편집과 정확한 Gmarket 글꼴 선택은 합성 영상으로 확인했고, 실제 상품 v2 Flow·배치·미관은 해당 작업의 실제 QA를 따릅니다. 현재 PC는 After Effects가 설치되어 있지 않습니다. JSX는 준비했지만 실행·AEP 저장·AE 렌더는 검증되지 않았고, 생성한 JSX 자체는 렌더 명령을 실행하지 않습니다. 기존 상품 샘플 MP4는 FFmpeg 결과이며, 이번 Remotion 편집 시험 MP4는 실제 Remotion 결과입니다. 연결 상태와 작업 증빙은 gitignore된 `.local/`·`jobs/`에 저장합니다.

실행에 필요한 조건은 편집 가능한 Figma 파일, 로그인된 Flow, 요청한 Image 2.5 high를 실행할 수 있는 이미지 도구입니다. 현재 Codex 내장 이미지 도구로 해당 모델·품질을 직접 지정할 수 있는지는 확인되지 않았습니다. 이번 샘플은 사용자가 허용한 내장 도구 대체 실행으로 진행했으며, 이를 Image 2.5 high 사양 확인으로 취급하지 않습니다. 대체 허용은 작업별로 기록합니다. 구독과 크레딧에는 서비스 한도가 있으며, 무제한·비용 0을 보장하지 않습니다. 별도 유료 API 자동 전환과 크레딧 자동 구매는 꺼져 있습니다.

Figma의 현재 `upload_assets`는 이미지용입니다. MP4는 검증된 네이티브 파일 삽입을 우선 사용하고, 가져온 VIDEO fill 노드 자체를 작업 사본으로 옮깁니다. 현재 연결에서 `use_figma`로 VIDEO fill을 직접 쓰는 방식은 지원되지 않았습니다. 프로토타입 재생을 확인한 뒤 GIF 대체본은 숨깁니다. 최종 동영상은 MP4와 재생 가능한 HTML 미리보기로도 제공하며, 정지 이미지 출력에 영상이 포함되었다고 보고하지 않습니다.

Figma 인증은 연결된 플러그인과 기존 브라우저 세션을 재사용합니다. 작업마다 로그인하거나 로그아웃하지 않습니다. 서비스가 인증을 만료시켰을 때만 정상 재인증이 필요합니다. 비밀번호를 저장소에 보관하지 않습니다.

이미지 검수에는 Pillow가 필요하며 Codex 제공 Python 런타임에 포함되어 있습니다. 별도 환경에서는 `requirements.txt`를 설치합니다. Windows 영상 도구는 `scripts/setup-media.ps1`로 프로젝트 `.tools/`에만 설치할 수 있습니다. 템플릿 Pretendard가 없으면 `figma_payload.py clone --font-fallback "Noto Sans KR"`로 사본에서만 지원 글꼴을 적용할 수 있습니다. 실제 리드 사본의 한글 렌더·줄바꿈 및 마스터 보존을 확인했습니다.
