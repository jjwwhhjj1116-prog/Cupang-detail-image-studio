# 리드 MP4의 Figma 배치와 재생 검증

실물 TYPE6 리드 샘플에서 Figma의 **File → Place image/video**로 최종 MP4 두 개를 가져와 작업용 사본에 배치하고, 프로토타입에서 두 영상이 실제 재생되는 것을 확인했다. 각각 5초·768×500 영상이었다. 다음 작업에서도 이 네이티브 파일 삽입 경로를 우선 사용하되, 파일 권한·메뉴·재생 결과는 해당 작업에서 확인한다.

현재 연결의 `upload_assets`는 이미지 업로드용이다. `use_figma`로 `VIDEO` fill을 직접 지정하는 시도는 지원하지 않는다는 오류를 반환했다. 네이티브 삽입으로 이미 만들어진 VIDEO fill 노드를 작업 사본 아래로 옮기는 방식은 작동했다. 따라서 MP4는 네이티브 UI로 가져오고, 도구로 확인된 노드의 부모·크기·위치를 조정한다. VIDEO fill을 새로 쓰는 방식으로 반복 시도하지 않는다.

## 기본 실행 경로

1. 검수된 최종 MP4 두 개의 파일 해시와 probe를 확인한다. 각 영상은 30fps·150프레임·5초이며 한글 자막이 포함되어야 한다. 원본 영상과 SRT는 별도로 보존한다.
2. Figma 작업 사본에서 영상 슬롯의 실제 보이는 크기와 부모 노드를 읽는다. 마스터 사본을 편집 대상으로 사용하지 않는다.
3. 연결된 브라우저 또는 데스크톱 제어 스킬로 **File → Place image/video**를 열고 실제 MP4 파일을 선택해 가져온다. 파일 선택·삽입은 Codex가 수행한다. 메뉴와 업로드 완료 상태를 화면에서 확인하고 불명확한 결과에 중복 삽입하지 않는다.
4. 가져온 노드의 실제 ID와 VIDEO fill을 확인한다. 해당 노드 자체를 제품 사본의 영상 영역으로 옮기고 원본 비율을 유지해 맞춘다. 기존 VIDEO fill을 교체하지 않는다. 영상 슬롯·자막띠가 잘리지 않는지 확인한다.
5. MP4가 들어간 뒤 기존 GIF 대체본은 사본 안에서 명확히 이름 붙여 숨긴다. 정지 포스터·재생 버튼·‘영상 제작 대기’ 문구가 영상 위를 가리지 않도록 정리한다. 마스터와 검수된 MP4 파일은 변경하지 않는다.
6. 사본의 프로토타입을 실제로 열어 두 리드가 각각 재생되는지 검수한다. 아래 재생 증빙을 작업 폴더에 저장한 뒤 편집본·프로토타입 링크와 이동 가능한 MP4/HTML 패키지를 제공한다.

## 재생 QA

프로토타입 페이지에서 실제 렌더된 `<video>` 요소를 읽어 각각의 `duration`, `videoWidth`, `videoHeight`, `currentTime`, `paused`, `ended`, `readyState`를 기록한다. 재생 시점을 달리해 `currentTime`이 진행하는지 확인한다. 반복 재생의 경우 시간 감소가 루프 복귀인지 구분한다. 두 요소를 각 리드에 연결할 수 있는 화면 위치나 부모 영역도 함께 기록한다. DOM 읽기는 페이지에 표시되는 영상 상태 확인에만 사용한다.

두 영상의 서로 다른 장면이 표시되는 스크린샷을 저장하고 제품·한글 자막·크롭·헤드라인 배치를 실제로 본다. 재생 중이라는 DOM 상태만으로 제품 보존이나 자막 가독성을 통과시키지 않는다. 정지 PNG 렌더는 배치 검수 증거이며 동작 재생의 단독 증거가 아니다. Figma 내부 재인코딩이 발생할 수 있으므로 로컬 MP4 해시와 삽입 기록을 연결하고, 재생 DOM의 크기·길이와 로컬 probe를 비교한다.

이번 네이티브 재생 확인의 범위는 리드 2개 샘플이다. 모든 샘플 QA가 통과하면 `sample_verified`로 기록하며 `page_complete:false`를 유지한다. 전체 TYPE 상세페이지 완료나 After Effects 실행·렌더 완료로 확대하지 않는다.

## GIF 대체 경로

네이티브 MP4 삽입이 해당 환경에서 실제로 막혔을 때만 GIF 경로를 사용한다. MP4 재생이 확인된 작업에서는 GIF를 숨긴 대체본으로 유지한다. 현재 연결에서 GIF 업로드 성공·정지 썸네일 표시만으로 애니메이션 재생을 입증할 수 없었으므로, GIF도 프로토타입에서 움직임을 직접 확인해야 한다. 대체본만 검증되었다면 MP4가 삽입된 Figma 편집본과 구분해 기록한다.

```powershell
ffmpeg -i lead-1.mp4 -filter_complex "[0:v]fps=15,scale=558:-1:flags=lanczos,split[s0][s1];[s0]palettegen[p];[s1][p]paletteuse" -loop 0 lead-1.gif
```

폭·프레임률은 실제 슬롯과 업로드 제한에 맞춰 정한다. 위 558px·15fps는 샘플 파생본의 예이며 최종 MP4는 30fps 그대로 보존한다. `upload_assets`로 GIF를 올릴 때 내부 인스턴스 ID 형식이 거부되면 실제로 확인한 사본의 상위 인스턴스에 업로드한 뒤 반환된 imageHash를 정확한 이미지 노드에 적용하고 상위의 임시 fill을 제거한다. 이는 IMAGE fill의 대체 절차이며 VIDEO fill에는 사용하지 않는다.

최종 파일은 MP4·SRT와 재생 가능한 `preview.html`로도 제공한다. `scripts/sample_delivery.py`는 리드 샘플을 이동 가능한 상대 경로로 묶는다. 정적 PNG/JPG에는 동영상이 재생되지 않는다. 업로드 URL·계정·실제 파일/노드 ID·개인 경로는 공개 문서에 기록하지 않는다.
