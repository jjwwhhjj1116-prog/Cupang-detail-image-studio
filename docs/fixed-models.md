# 고정 얼굴·캐릭터 시트와 변경 가능한 스타일

와이홉·유앤채의 착용 이미지와 영상에서 사용하는 얼굴은 F01(여자), M01(남자) 두 프로필이다. 승인된 기준 사진·캐릭터 시트·추가 표정 시트의 공통 참조 6개는 `assets/models/`에 포함하여 다른 PC에서도 동일하게 사용한다. `config/models.json`에는 기준 얼굴, 캐릭터 시트, 표정 시트의 실제 버전·파일 경로·SHA-256·등록 상태를 기록한다. 파일을 원본과 검수한 실제 값만 등록하며 아직 없는 시트의 경로나 해시를 추정해 쓰지 않는다. 고객 제품 사진과 작업별 생성물·미승인 후보·계정 정보는 이 공통 참조에 포함하지 않는다.

F01은 사용자가 “여자는 굿 고정”으로 승인한 기준 얼굴이다. M01-v6은 사용자가 “이 얼굴로만”이라고 마지막으로 지정하고 확정한 단독 남자 사진 자체다. 원본 얼굴을 기준으로 저장하며 거절한 v1~v5 생성 후보를 얼굴 참조에 섞지 않는다. 의상·헤어스타일·표정 시험 이미지도 기준 얼굴을 대체하지 않는다. 파생 결과는 원본과 비교하여 정체성 변화를 검수한다.

## 캐릭터 시트와 표정 시트

각 기준 얼굴에서 **정면·왼쪽 측면·오른쪽 측면·뒷모습**과 **가벼운 미소·웃음·집중·놀람·몽환적 표정**을 파생한 캐릭터 시트를 만든다. 실제 등록 정보는 각 모델의 `character_sheet`에 `revision`, `file`, `sha256`, `views`, `expressions`로 기록한다. 기준 얼굴 사진은 계속 정체성의 최우선 참조이며 캐릭터 시트는 각도·표정의 일관성을 보조한다.

추가 화보 표정은 각 모델의 `expression_sheet`에 별도 버전·파일·해시로 등록한다. 몽환적으로 힘을 뺀 시선, 살짝 열린 입술, 시선을 옆으로 둔 표정, 낮춘 턱, 부드러운 바람결 같은 연출을 제품·화보 콘셉트에 맞춰 사용한다. 사용자가 제공한 패션 사진은 시선·표정·빛·분위기의 참고이며 그 사진의 얼굴을 F01/M01로 바꾸어 쓰지 않는다.

시트의 앞·옆·뒤 모습은 기준 얼굴에서 생성한 파생 결과다. 원본 사진에 없는 뒷모습이나 측면 해부학을 실제 촬영 사실로 단정하지 않는다. 원본과 얼굴 형태·눈매·코·입·피부 톤을 비교하고, 다른 얼굴처럼 보이는 컷은 재사용 참조로 등록하지 않는다. 뒷모습은 헤어·자세 등 연출의 비교 자료이며 얼굴 일치 검증을 대신하지 않는다. 시트의 의상과 헤어는 비교를 위한 기본 스타일이며 매 광고에 고정된 외모 스타일을 요구하지 않는다.

캐릭터 시트와 표정 시트는 **제작 참조**다. 상세페이지나 리드 영상에 시트 전체를 광고 이미지로 그대로 배치하지 않고 해당 장면에 필요한 얼굴·각도·표정 정보만 참조한다. 사진 기반 제품 구조 검수와 얼굴 정체성 검수를 각각 수행한다.

## 의상과 헤어스타일

**얼굴 정체성은 고정하고 의상·헤어스타일은 변경한다.** 제품, 계절과 촬영 콘셉트에 맞춰 현대적인 한국 패션 화보 스타일로 바꾼다. 매 작업마다 같은 가죽 재킷이나 니트를 반복하지 않고 묶은 머리·풀어 내린 머리·가르마·웨이브·바람결 등도 콘셉트에 맞춰 설계한다. 같은 연속 장면 안에서는 의상·헤어스타일·액세서리를 유지하여 영상 연결을 자연스럽게 만든다. 허용된 스타일 변경을 컷마다 다시 승인받지 않는다.

imagegen 생성에 반드시 **실제 기준 얼굴 사진·필요한 캐릭터/표정 시트·원본 제품 사진**을 함께 첨부한다. 얼굴 정체성이 충돌하면 기준 얼굴을 우선하고 제품 구조가 충돌하면 원본 제품 사진을 우선한다. 앞·옆 착용 컷도 이 참조에서 파생하며 얼굴 형태·눈매·코·입·피부 톤을 비교한다. 장면별로 다른 남녀 얼굴을 새로 만드는 방식은 사용하지 않는다. 모자·색·홀·로고·봉제 등 제품 특징은 별도로 검수한다. AI 생성은 참조가 있어도 얼굴과 제품이 달라질 수 있으므로 실제 결과 확인을 생략하지 않는다.

Flow에는 검수한 생성 장면, 필요한 얼굴/제품 참조를 **리드당 최대 5개** 안에서 선택·재사용한다. 시트 전체·모든 표정·모든 제품 사진을 한꺼번에 필수 입력으로 요구하지 않는다. 리드별 한 번의 생성 요청 안에서 5개 장면을 구성하고 최종 5초 타이밍과 자막 모드 처리는 로컬 편집으로 수행한다.

Codex가 작업을 인수하면 다음 도구로 새 job 버전을 만든다. 사용자가 직접 입력할 절차가 아니다.

```powershell
python scripts/models.py status
python scripts/models.py bind jobs/sample/job.json --workspace jobs/sample --output jobs/sample/job-f01.json --model-ids female-f01
```

`--model-ids`를 생략하면 F01/M01 기본 배정을 사용한다. 미승인 후보, 해시가 다른 참조, 기존 job 덮어쓰기는 거부한다. 새 작업의 binding은 등록된 기준 얼굴과 필요한 시트를 `input/models/`에 복사하고 각 프로필의 `character_sheet`·`expression_sheet` 파일·버전·해시를 기록한다. 제작 계획은 얼굴·시트 파일과 모델 배정의 변경을 감지한다. 캐릭터 시트가 없는 기존 작업은 역사로 재개하되 새 작업의 필수 참조를 기존 작업에 소급해 붙이지 않는다. 얼굴이나 참조 시트가 바뀌면 이전 영상의 QA를 그대로 재사용할 수 없다.

새 binding에는 기본 캐릭터 시트와 추가 표정 시트 **둘 다** 등록되어 있어야 한다. 고정 모델을 결속한 이미지·원본 영상·최종 영상 QA에는 `model_identity` 검수 근거를 기록한다. 착용 컷은 실제 기준 얼굴과 비교하고 제품 단독 컷은 사람이 없음을 확인해 기록한다. 참조 파일의 해시 검증과 생성 결과의 얼굴 검수는 함께 수행한다.

다른 PC에서는 저장소를 복제한 뒤 [새 PC 설정](new-pc-setup.md)을 실행하고 `assets/models/`의 등록된 기준 얼굴·시트 해시를 확인한다. 개인 폴더를 수동으로 복원하거나 얼굴을 다시 생성할 필요가 없어야 한다. 참조가 없거나 해시가 다르면 해당 문제를 해결하며 설명만 보고 얼굴을 다시 만들지 않는다. 모델 교체 요청은 새 버전으로 기록하고 이전 승인 얼굴·시트·제작 이력을 보존한다. 시트 제작이나 워크프로세스 저장은 참조 준비이며, 선택 TYPE의 상세 이미지·전체 Figma 배치 완료를 뜻하지 않는다.
