# 리드 영상 샘플에서 전체 상세페이지까지

사용자가 브랜드·TYPE·하디 원고를 전달하면 Codex가 실행한다. 기존 채팅에 사진이 있으면 `read_thread`의 실제 attachments 경로로 가져오고 원본을 보존한다. 채팅 화면의 작은 썸네일이나 참고용 다른 상품 사진을 제품 원본으로 대체하지 않는다.

## 고정 실행 순서

1. `jobs/<job_id>/input/`에 원고와 사진을 저장하고 브랜드, 참조 사진 해시, 원고 버전을 기록한다. 새 샘플은 `sample-job-v2.json`에 리드 2개를 담고 `plan --scope lead-sample`로 준비한다. 기본은 `single-source-v2`이며 원본 MP4·표시 SRT·최종 MP4, 리드당 세 개를 추적한다. 기존 v1 파일과 계획은 덮어쓰지 않는다.
2. Figma에서 선택 타입의 리드 헤드라인 2개와 별도 영상 형제 그룹 2개를 실제로 읽는다. 작업용 사본을 만들고 가로세로 비율을 기록한다. 누락된 Pretendard는 사본에만 지원되는 Noto Sans KR 굵기로 대응시키고 렌더를 검수한다.
3. 각 리드의 1~5번을 **한 번 제출할 타임스탬프 스토리보드**로 설계한다. 착용 화보·제품 회전·디테일에 구도와 동작을 연결한다. 장면별로 Flow 요청 다섯 개를 만들지 않는다. 생성 이미지·영상에는 한글을 그리지 않는다.
4. 각 리드의 참조 이미지 1~5개를 선택·재사용하고 부족한 참조만 imagegen으로 보충한다. 시작 이미지 열 장은 필수가 아니다. 이미지 모델·품질이 실제 도구에서 지정되지 않으면 기록한다. 사용자가 허용한 대체 실행은 작업별로 남기며 다른 작업까지 허용 범위를 넓히지 않는다.
5. 제품의 형태, 홀, 챙, 봉제, 스트랩을 참조와 비교한다. 불일치한 컷만 다시 만든다. 비교용 일반 모자는 별도 소품임을 명시하고 판매 제품과 혼동하지 않는다.
6. 로그인된 Flow에서 프로젝트를 열고 실제 UI의 **모델·지원 길이·출력 x1·표시 비용**을 확인·캡처한다. 해당 정보를 증빙 JSON에 저장하고 `studio.py generation-start ... lead-1 ...`로 단일 요청을 예약한 뒤 제출한다. 리드2도 같은 절차다. 기존 크레딧을 사용하며 추가 구매하지 않는다. 과거 메뉴 위치·지원 길이·가격을 추정하지 않는다.
7. 스토리보드를 **리드당 한 번** 생성하고 원본 MP4 하나씩을 보존한다. 5초가 미지원이면 지원 길이 하나로 생성한 뒤 편집한다. 요청 ID·프로젝트·실제 결과 ID를 기록한다. 불명확한 결과는 기존 카드부터 확인하며 자동 재제출·장면별 생성 전환을 하지 않는다.
8. 한 원본에서 다섯 장면의 실제 구간을 검사하고 `media.py --source ... --edit-map ... --style fullbleed-motion --caption-band 0 --font .../GmarketSansTTFBold.ttf`로 편집한다. 구간당30프레임·리드당150프레임이다. 짧은 안전 구간은 edit-map의 `source_duration`으로 명시한다. 화면을 채운 영상 위에 **Gmarket Sans Bold** 키워드·보조문구를 배치하고 검은 하단바는 만들지 않는다. 줌·슬로는 검수된 소스로 표현하며 실제 회전이 없는 360도 연출을 만들지 않는다. 편집 카피와 사유는 job overlay에 기록하고 원문은 별도 SRT·JSON으로 보존한다. 자세한 실행은 `docs/fullbleed-v2.md`를 따른다. AE가 없는 현재 PC에서는 FFmpeg MP4와 JSX 준비를 구분하며 AEP/AE 렌더 완료를 주장하지 않는다.
9. 0·29·30·59·60·89·90·119·120·149프레임을 확인해 장면·자막 경계, 한글, 제품 보존, 손/스트랩 변형을 검수한다. 기계 검사만으로 동작 검증을 통과시키지 않는다.
10. Figma 사본에 헤드라인을 배치하고 **File → Place image/video**로 최종 MP4 두 개를 실제 가져온다. 삽입된 VIDEO fill 노드 자체를 사본의 영상 영역으로 옮겨 배치하고 GIF 대체본은 숨긴다. 현재 연결에서 VIDEO fill 직접 지정은 지원되지 않으므로 가져온 노드의 fill을 새로 쓰지 않는다. HTTPS 프로토타입을 열어 두 영상의 실제 DOM에서 길이·크기·시간 진행을 확인하고 서로 다른 시점의 스크린샷으로 제품·자막·레이아웃을 검수한다. 상세 절차는 `docs/figma-media.md`를 따른다. 해당 환경에서 네이티브 삽입이 실제로 막혔을 때만 대체 경로를 검토하고 미완료 항목을 기록한다. 정지 포스터를 영상으로 표시하지 않는다.
11. **다운로드할 최종 MP4 두 개**·표시/원문 자막·검수 기록·미리보기·Figma 링크를 제공한다. `complete`의 `sample_verified`와 전체 `page_complete:false`를 구분한다. 전체 제작으로 이어갈 때 `--scope full --reuse-sample`로 동일 입력의 통과 파일과 소비한 요청 슬롯을 함께 재사용한다.

## 운영 기록

작업은 실행 중인 Codex가 위 도구를 호출하여 수행한다. 별도 상주 프로그램이 채팅을 감시하는 구조가 아니다. 로그인은 기존 세션을 재사용하며 실제 인증 만료 때만 정상 재인증한다. 파일 누락·제품 불일치가 있으면 기존 결과 다운로드나 로컬 편집으로 해결 가능한지 확인한다. Flow의 추가 생성은 자동 수행하지 않으며 필요한 경우 별도 지시를 받는다. 재시작만으로 새 요청을 예약하지 않는다.

브라우저 업로드가 로컬 파일 URL 권한 오류를 반환하면 연결된 확장 프로그램의 해당 권한을 확인한다. 사용자가 이미 켰다면 먼저 업로드를 다시 확인하며 같은 요청을 반복하지 않는다. 확장 연결이 재시작되어 브라우저가 실제로 끊겼을 때만 재연결하고, Flow의 화면에 표시된 계정이 로컬 설정과 일치하는지 확인한다. 단순 탭 누락에는 기존 브라우저의 탭을 다시 얻는다.

소스 QA는 전체 원본 대신 실제로 선택한 연속 구간에 결속할 수 있다. 이 경우 시작·배타적인 종료 시각·구간 길이·제외 구간·파일 해시를 기록하고 편집기가 정확한 구간만 사용해야 한다. 0.5초 소스를 최종 1초로 늘려도 QA 범위 밖 원본 프레임을 포함하지 않는다. 달리는 장면의 홀·봉제선 소실, 스트랩 조작 후 부품 변경 등은 원본과 비교하여 실패 처리한다. 안정된 시작 프레임 하나만으로 영상 전체를 승인하지 않는다.

이 실행서가 있다고 실제 생성 시험이 통과한 것은 아니다. 샘플의 실제 진행 상태와 막힌 조건은 해당 `jobs/<job_id>/`의 상태·검수 기록이 근거다.
