# 리드 영상 샘플에서 전체 상세페이지까지

사용자가 브랜드·TYPE·하디 원고를 전달하면 Codex가 실행한다. 기존 채팅에 사진이 있으면 `read_thread`의 실제 attachments 경로로 가져오고 원본을 보존한다. 채팅 화면의 작은 썸네일이나 참고용 다른 상품 사진을 제품 원본으로 대체하지 않는다.

## 고정 실행 순서

1. `jobs/<job_id>/input/`에 원고와 사진을 저장하고 브랜드, 참조 사진 해시, 원고 버전을 기록한다. 샘플은 `sample-job.json`에 리드 2개를 담고 `plan --scope lead-sample`로 준비한다.
2. Figma에서 선택 타입의 리드 헤드라인 2개와 별도 영상 형제 그룹 2개를 실제로 읽는다. 작업용 사본을 만들고 가로세로 비율을 기록한다. 누락된 Pretendard는 사본에만 지원되는 Noto Sans KR 굵기로 대응시키고 렌더를 검수한다.
3. 각 리드의 1~5번을 별도 컷으로 설계한다. 장면마다 원본 참조 파일을 연결하고 촬영 구도, 시작 자세, 한 동작만 명시한다. 이미지에는 한글 자막을 그리지 않는다.
4. imagegen으로 시작 이미지 10개를 각각 생성한다. 모델·품질이 실제 노출 도구에서 지정되지 않으면 그 사실을 기록한다. 사용자가 허용한 대체 실행은 작업별 설정에 남겨 반복해서 묻지 않는다. 다른 작업까지 자동으로 허용 범위를 넓히지 않는다.
5. 제품의 형태, 홀, 챙, 봉제, 스트랩을 참조와 비교한다. 불일치한 컷만 다시 만든다. 비교용 일반 모자는 별도 소품임을 명시하고 판매 제품과 혼동하지 않는다.
6. 로그인된 Flow에서 해당 작업 프로젝트를 열거나 만든다. 현재 화면의 모델·프레임 입력·16:9·출력 x1·소재 길이·크레딧을 확인한다. Veo 3.1 Quality를 지원하면 우선 사용하되 오래된 메뉴 위치를 추정하지 않는다. 기존 구독 크레딧으로 진행하고 추가 구매하지 않는다.
7. 시작 이미지를 실제 파일 업로드로 넣고 해당 컷의 동작 프롬프트로 생성한다. 생성마다 작업 ID·컷 ID·프로젝트 링크·제출 여부·결과를 기록한다. 불명확한 결과는 기존 카드부터 확인하고 중복 제출하지 않는다. 원본 MP4 10개를 보존한다.
8. 컷마다 동작이 잘 보이는 검수된 연속 구간을 골라 `media.py`로 30fps·구간당30프레임·리드당150프레임을 합성한다. 짧은 안전 구간은 `--source-durations`로 길이를 명시해 최종 1초로 늘린다. 결과는 리드별 한 영상, 총 두 영상이다. 사용자 자막 원문을 각각 0~1/1~2/2~3/3~4/4~5초에 넣는다. 힙한 타이포 요청은 `--style kinetic`과 `docs/after-effects.md`의 JSX 생성기를 사용한다. 원문 자막은 유지하고 강조 단어만 움직인다. 무음 출력하더라도 Flow 원본은 보존한다.
9. 0·29·30·59·60·89·90·119·120·149프레임을 확인해 장면·자막 경계, 한글, 제품 보존, 손/스트랩 변형을 검수한다. 기계 검사만으로 동작 검증을 통과시키지 않는다.
10. Figma 사본에 헤드라인을 배치하고 **File → Place image/video**로 최종 MP4 두 개를 실제 가져온다. 삽입된 VIDEO fill 노드 자체를 사본의 영상 영역으로 옮겨 배치하고 GIF 대체본은 숨긴다. 현재 연결에서 VIDEO fill 직접 지정은 지원되지 않으므로 가져온 노드의 fill을 새로 쓰지 않는다. HTTPS 프로토타입을 열어 두 영상의 실제 DOM에서 길이·크기·시간 진행을 확인하고 서로 다른 시점의 스크린샷으로 제품·자막·레이아웃을 검수한다. 상세 절차는 `docs/figma-media.md`를 따른다. 해당 환경에서 네이티브 삽입이 실제로 막혔을 때만 대체 경로를 검토하고 미완료 항목을 기록한다. 정지 포스터를 영상으로 표시하지 않는다.
11. 영상2개·SRT2개·검수 기록·미리보기·Figma 링크를 제공한다. `complete`의 `sample_verified`와 전체 `page_complete:false`를 구분한다. 전체 제작으로 이어갈 때 `--scope full --reuse-sample`로 동일 입력의 통과 파일을 재사용한다.

## 운영 기록

작업은 실행 중인 Codex가 위 도구를 호출하여 수행한다. 별도 상주 프로그램이 채팅을 감시하는 구조가 아니다. 로그인은 기존 세션을 재사용하며, 실제 인증 만료가 발생할 때만 정상 재인증한다. 파일 누락·생성 실패·제품 불일치가 있으면 해당 컷만 보정하고 이미 통과한 결과를 다시 생성하지 않는다.

브라우저 업로드가 로컬 파일 URL 권한 오류를 반환하면 연결된 확장 프로그램의 해당 권한을 확인한다. 사용자가 이미 켰다면 먼저 업로드를 다시 확인하며 같은 요청을 반복하지 않는다. 확장 연결이 재시작되어 브라우저가 실제로 끊겼을 때만 재연결하고, Flow의 화면에 표시된 계정이 로컬 설정과 일치하는지 확인한다. 단순 탭 누락에는 기존 브라우저의 탭을 다시 얻는다.

소스 QA는 전체 원본 대신 실제로 선택한 연속 구간에 결속할 수 있다. 이 경우 시작·배타적인 종료 시각·구간 길이·제외 구간·파일 해시를 기록하고 편집기가 정확한 구간만 사용해야 한다. 0.5초 소스를 최종 1초로 늘려도 QA 범위 밖 원본 프레임을 포함하지 않는다. 달리는 장면의 홀·봉제선 소실, 스트랩 조작 후 부품 변경 등은 원본과 비교하여 실패 처리한다. 안정된 시작 프레임 하나만으로 영상 전체를 승인하지 않는다.

이 실행서가 있다고 실제 생성 시험이 통과한 것은 아니다. 샘플의 실제 진행 상태와 막힌 조건은 해당 `jobs/<job_id>/`의 상태·검수 기록이 근거다.
