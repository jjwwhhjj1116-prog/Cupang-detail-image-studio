# 다른 Windows PC에서 같은 제작 환경 시작하기

각 PC에서 이 저장소를 Codex 프로젝트로 열면 같은 제작 지침·TYPE 구조·고정 얼굴 참조를 사용한다. 처음 준비하는 PC 3곳에서 아래 설정을 한 번씩 실행한다. PC마다 다른 설치 경로는 `.local/runtime.json`에 저장하며 사용자 전역 Codex 설정을 덮어쓰지 않는다.

## 첫 새 채팅에 붙여 넣을 문구

저장소를 연 Codex의 새 채팅에 다음 문구를 붙여 넣는다. 로컬 작업본이 아직 없으면 이 문구로 복제와 설정부터 요청할 수 있다.

```text
https://github.com/jjwwhhjj1116-prog/Cupang-detail-image-studio.git

이 PC에서 이 저장소의 상세페이지 제작 워크프로세스를 설정해줘.
이미 로컬 작업본이 있으면 재사용하고, 없으면 새 폴더에 복제해줘.
저장소의 AGENTS.md, .agents/skills/detail-page-production/SKILL.md,
config/studio-portability.json, docs/new-pc-setup.md를 읽어줘.

scripts/setup-studio.ps1을 실행하고 누락된 공식 Remotion 스킬은
config/remotion-skills.lock.json의 고정 버전으로 설치해줘.
scripts/doctor.py로 도구·글꼴·승인 모델 참조·스킬·에이전트 설정을 검증해줘.
저장소의 이미지 기획·모션 편집·Figma 조립 에이전트 역할을 필요한 작업에 자동 사용해줘.
승인된 F01/M01 얼굴·캐릭터/표정 시트와 사용자 소유 Figma 마스터 연결을 재사용해줘.
Figma와 Flow는 이 PC의 기존 로그인 세션을 먼저 사용하고,
실제 최초 로그인이나 인증 만료 때만 정상 인증을 안내해줘.
비밀번호를 저장하거나 다른 PC의 쿠키를 복사하지 마.
설정 완료와 실제 제작 도구의 연결 검증을 구분해서 알려줘.

실제 제작은 내가 하디의 1~4단계를 마치고 원고·제품 사진·브랜드·TYPE·자막 모드를 전달하면 시작해.
영상은 리드당 Flow 생성 한 번·출력 x1로 원본을 만들고 로컬에서 각각 5초로 편집해줘.
자막 있음은 Gmarket Sans Bold 모션 타이포, 자막 없음은 글자·띠 없이 영상만 제공해줘.
영상 제작을 제외한 나머지는 선택한 템플릿 TYPE에 맞춰 AI 이미지를 생성·교체하여
완성된 편집 가능한 Figma 파일로 제공해줘.
리드1·리드2 MP4는 각각 다운로드하게 하고 전체 결과를 실제 검수해줘.
이미 허용된 구독·크레딧 내 작업의 컷별 승인은 반복하지 마.
```

새 폴더로 복제한 경우 이후 업무는 그 폴더를 Codex 프로젝트로 열어 진행한다. 이렇게 하면 저장소의 스킬과 에이전트 설정을 다음 새 채팅에서도 발견할 수 있다. 첫 채팅의 설정 요청만으로 제품 이미지·영상·전체 Figma가 제작된 것으로 보고하지 않는다.

Git 명령이 없는 PC에서는 Codex가 사용 가능한 Git 실행 파일을 먼저 찾는다. 없으면 GitHub의 저장소 ZIP을 새 폴더에 받아 설정을 시작할 수 있다. 최신 변경은 로컬 수정 내용을 보존한 상태에서 Git으로 갱신하거나 새 ZIP 작업본에서 인수한다. 설치 스크립트 자체는 Git 명령을 필요로 하지 않는다.

## 설정 실행

Codex가 저장소 루트에서 실행할 기본 명령이다. 사용자가 수동으로 실행할 필요는 없다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ./scripts/setup-studio.ps1
```

기본 실행은 PC별 연결·경로를 준비하고 필요한 로컬 도구와 고정 버전 스킬을 설치한 뒤 환경 검사를 수행한다. 기존 유효한 설치를 재사용한다. Remotion 스킬은 저장소의 `.agents/skills/`에 누락된 항목을 설치하고 잠금 파일의 해시를 확인한다. 설치로 생긴 공급자 스킬 파일과 PC별 실행 도구는 GitHub에 다시 올리지 않는다.

| 저장소에서 이어받는 항목 | 새 PC에서 준비하거나 확인하는 항목 |
|---|---|
| 제작 `AGENTS.md`와 프로젝트 스킬 | Codex에서 이 저장소를 프로젝트로 열기 |
| TYPE1~7 구조와 제작 설정 | live Figma 레이어·글꼴·편집 권한 확인 |
| 공식 Remotion 스킬 잠금 파일 | 누락 스킬, Python·Node·영상/렌더 도구 준비 |
| 승인 얼굴·캐릭터/표정 시트 6개와 해시 | 실제 참조 파일 해시 검사 |
| 사용자 소유 Figma 마스터 메타데이터 | 해당 계정의 정상 최초 로그인과 마스터 접근 확인 |
| 이미지·모션·Figma 에이전트 역할 | 새 프로젝트 채팅에서 설정 발견 여부 확인 |

공통 연결 메타데이터는 `config/studio-portability.json`에서 읽고 PC별 연결 파일은 `.local/connections.json`에 만든다. 원본 유료 `.fig`를 공개 GitHub에 넣거나 다른 소유자의 공유 권한을 바꾸지 않는다. 다른 PC에서도 이미 가져온 사용자 소유 마스터에서 제품 작업 사본을 만든다.

기본 설정 실행으로 `.local/runtime.json`을 만든 뒤 네트워크 설치 없이 현재 상태만 검사하려면 다음 명령을 사용한다. 아직 실행 경로 기록이 없는 첫 PC에서는 기본 설정부터 실행한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ./scripts/setup-studio.ps1 -CheckOnly
```

자동 탐색으로 실행 도구를 찾지 못했지만 PC에 설치되어 있으면 `-PythonExe`·`-NodeExe`로 해당 실행 파일을 지정한다. 도구의 실제 경로는 `.local/runtime.json`에 기록하며 다른 PC의 절대 경로를 그대로 복사하지 않는다.

기존 설치의 모든 고정 npm 버전이 맞으면 실행 중인 Studio를 유지하고 재설치를 생략한다. 버전이 달라 재설치가 필요한데 Windows에서 파일 사용 중 오류가 나면 해당 저장소의 Remotion Studio 미리보기를 닫고 다시 실행한다.

## 검사 결과와 최초 인증

환경 검사만 다시 실행할 때는 탐색된 Python을 사용한다. 아래의 `python`은 PC에서 확인한 실행 파일로 바꿀 수 있다.

```powershell
python scripts/doctor.py --repo . --output .local/doctor.json
```

`local_setup_ready`는 로컬 설정·도구·스킬·참조 검사가 통과했다는 뜻이다. 검사 보고서의 `production_ready`는 실제 제작 연결 검증 전까지 `false`이며 `live_verification_required` 항목은 Codex가 실제 연결 도구로 확인해야 한다. 이미지 생성 도구의 사용 가능 여부, Figma 편집·MP4 삽입, Flow 계정·모델·길이·x1·표시 비용은 로컬 파일 검사만으로 통과시키지 않는다. 첫 실제 작업에서 연결된 도구와 화면을 확인하고 결과를 저장한다.

Figma 플러그인과 Flow 브라우저 로그인은 각 PC에 필요하다. 먼저 현재 PC의 연결과 기존 세션을 사용하고 실제 로그아웃 상태일 때만 정상 로그인한다. 추가 인증은 서비스의 정상 절차로 처리하며 비밀번호를 채팅에 보내거나 저장소에 넣지 않는다. 로그인된 세션을 작업 후 로그아웃하지 않으며 다음 작업에서도 재사용한다.

## 자동 사용하는 제작 역할

프로젝트 제작 스킬은 `.agents/skills/detail-page-production/`에 있고, 에이전트 역할은 `.codex/agents/`에 포함된다. `.codex/config.toml`의 프로젝트 설정을 사용하며 전역 설정을 바꾸지 않는다. 총괄 Codex가 독립적으로 진행할 수 있는 작업에 아래 역할을 사용하고 전체 결과를 다시 검수한다.

| 역할 | 담당 범위 |
|---|---|
| `detail_image_director` | 원고·선택 TYPE의 실제 슬롯 분석, 고정 얼굴·제품 참조를 사용한 이미지 제작 |
| `detail_motion_editor` | 리드별 단일 Flow 원본 확인, 5초 편집, 선택한 자막 모드의 로컬 Remotion 렌더 |
| `detail_figma_assembler` | 사용자 소유 작업 사본의 이미지·편집 가능한 카피 조립, 영상 삽입·배치 검수 |

역할별 작업을 나누어도 리드당 생성 예약은 하나이며 같은 Flow 요청을 중복 제출하지 않는다. 파일과 슬롯 담당 범위를 나누고 최종 QA를 한 곳에서 확인한다. 프로젝트 설정의 동시 실행 한도를 따른다.

## 설정 이후 전체 제작 요청

하디 채팅에서 사용자가 1~4단계를 완료한 뒤 다음 형식으로 원고와 원본 제품 사진을 전달한다.

```text
전체 제작 시작. 브랜드: 와이홉 / TYPE: TYPE6 / 영상: 자막 있음.
아래는 하디 최종 원고이며 첨부한 사진이 원본 제품 사진이야.
승인된 여자·남자 얼굴을 유지하고 의상·헤어는 제품과 콘셉트에 맞춰 바꿔줘.
리드 영상 두 개를 제작하고, 영상 제작을 제외한 나머지는 선택한 템플릿 TYPE에 맞춰
AI 이미지를 생성·교체하여 완성된 편집 가능한 Figma 파일로 제공해줘.
리드1·리드2 MP4는 각각 다운로드하게 해줘.
```

브랜드는 와이홉·유앤채, TYPE은 TYPE1~7, 영상은 자막 있음·없음 중 사용자가 지정한 값을 저장한다. 실제 템플릿의 복수 이미지 슬롯과 편집 가능한 카피·표를 모두 채운다. 확인하지 않은 치수·소재·사은품·후기를 만들지 않는다. 얼굴은 공통 승인 참조를 유지하고 의상·헤어스타일은 콘셉트마다 바꾸되 연속 장면에서는 유지한다.

허용된 구독/크레딧 범위에서는 생성·편집·배치를 단계마다 다시 승인받지 않고 진행한다. 추가 크레딧 구매나 별도 유료 API 전환은 자동으로 하지 않는다. 자막 선택을 바꿀 때 기존 Flow 원본을 재사용하고 로컬에서 편집한다.

최종 완료는 **선택 TYPE을 채운 편집 가능한 Figma 결과, 각각 다운로드할 리드1·리드2 MP4, 전체 슬롯·제품·고정 얼굴·카피·실제 영상 재생 검수**까지 끝난 상태다. 환경 설정 통과, 스킬 설치, 리드 샘플만으로 전체 완료를 표시하지 않는다. 상세 기준은 [제작 절차](production-workflow.md)를 따른다.

## PC 간 작업 이어가기

코드·공통 설정·승인 모델 참조는 GitHub에서 이어받는다. `jobs/`, `.local/`, `.tools/`의 고객 자료·제작 결과·계정 세션·PC별 설치는 공개 저장소로 동기화하지 않는다. `.local/machine.json`의 PC 식별자를 새 작업 ID에 포함해 각 PC의 작업을 구분한다. 다른 PC에서 같은 작업을 재개하려면 해당 작업 폴더를 별도로 옮기고 원본·출력·예약 상태·QA 해시를 확인한다. 이미 제출한 Flow 요청이나 완료한 생성물을 새 PC에서 다시 만들지 않는다. 한 작업을 재개하는 동안 다른 PC가 같은 작업의 생성 요청을 동시에 수행하지 않게 담당 PC를 한 곳으로 정한다.

프로젝트의 스킬과 에이전트는 Codex의 공식 [스킬 검색 규칙](https://learn.chatgpt.com/docs/build-skills)과 [프로젝트 에이전트 설정](https://learn.chatgpt.com/docs/agent-configuration/subagents)에 맞춰 저장했다. 에이전트는 별도 프로그램을 실행 파일로 설치하는 방식이 아니라 저장소에 함께 있는 역할 설정을 Codex가 읽어 실행한다. 구형 클라이언트가 역할 설정을 로드하지 못하면 업데이트가 가능한지 확인하고, 그동안 같은 지침을 기본 하위 에이전트에 전달한다.
