# 4단계 이후 자동 제작 절차

## 고정 제작 선택

하디 원고 수령 뒤 Codex가 **브랜드(와이홉/유앤채)·TYPE1~7·`caption_mode`(자막 있음/없음)**과 원본 제품 사진을 작업에 저장한다. 이미 받은 선택은 다시 묻지 않는다. 착용 컷은 승인된 F01/M01의 기준 얼굴, 등록된 정면·측면·뒷모습 캐릭터 시트와 표정 시트를 함께 참조한다. 얼굴은 [고정 모델 규칙](fixed-models.md)대로 유지하고 **의상과 헤어스타일은 제품·계절·화보 콘셉트에 맞춰 바꾼다.** 연속 장면의 의상·헤어스타일은 유지한다.

전체 제작 요청은 리드 1·2와 나머지 모든 원고 항목을 포함한다. 현재 TYPE6의 **3~18에 필요한 AI 이미지·카피·사양을 모두 제작하여 사용자 소유 Figma 템플릿의 작업 사본을 채우는 것**이 최종 범위다. 항목마다 새 래스터 이미지 한 장을 만들도록 고정하지 않고 실제 템플릿의 복수 이미지 슬롯과 편집 가능한 텍스트/표 역할을 따른다. 다른 TYPE은 각 타입의 번호와 구조에 맞춰 매핑한다.

Flow는 리드당 한 번 생성하고 로컬에서 정확한 5초 무자막 편집본을 만든다. 그 다음 [Remotion](remotion-local.md)으로 선택한 자막 모드를 렌더한다. 자막 있음은 Gmarket Sans Bold 모션 타이포, 자막 없음은 글자·띠 없이 영상만 출력한다. 이미 생성한 원본과 예약을 재사용하므로 자막 선택 변경으로 Flow를 다시 생성하지 않는다. 두 모드 모두 실제 결과 QA와 다운로드 MP4를 제공한다.

## 인수 경계

사용자는 하디 고정 채팅에서 1) 시작, 2) 제품 사진 제공, 3) 타입 선택, 4) 타입별 최종 프롬프트 수령을 한다. Codex가 원고와 사진을 전달받는 시점부터 자동 제작이 시작된다. 다른 ChatGPT 채팅을 상시 감시하거나 사용자의 메시지를 자동 전송하는 기능은 포함하지 않는다. 같은 자료를 반복해서 입력하게 하지 않는다.

작업 시작에 필요한 입력은 **브랜드(와이홉/유앤채), TYPE1~7, 영상 자막 모드, 최종 프롬프트, 원본 제품 사진**이다. 프롬프트에서 타입을 확실히 알 수 있으면 다시 묻지 않는다. 자막 선택을 생략하면 기존 호환을 위해 자막 있음으로 저장한다. 승인된 모델·캐릭터 시트·표정 시트는 등록된 참조를 재사용하고 작업마다 새 얼굴을 고르지 않는다. 소재·세탁법·치수·구성품·실제 옵션·사은품 등은 판매자가 확인한 값만 사용한다. 실제 로고가 없으면 정확한 브랜드명을 편집 가능한 텍스트로 넣고 템플릿 스타일을 따른다.

## 자동 실행

| 단계 | Codex가 할 일 | 완료 증거 |
|---|---|---|
| 인수 | 원고·원본 제품사진 보존, 브랜드·TYPE·자막 모드 저장 | 원본 파일, job.json |
| 모델 연결 | 기준 얼굴·캐릭터 시트·표정 시트의 실제 파일 확인, 의상/헤어 콘셉트 설계 | 참조 버전·경로·해시와 모델 배정 |
| 사실 검수 | 사진 관찰/판매자 확인/창작 카피를 구분 | 근거·누락 목록 |
| 슬롯 연결 | 실제 Figma 노드 확인, 선택 타입 복제 | live ID 및 복제 ID 매핑 |
| 컷 설계 | 리드 1·2 및 나머지 전체 항목의 슬롯별 목적·구도·배경·크롭 설계 | 복수 이미지 슬롯을 포함한 전체 작업 목록 |
| 이미지 | TYPE6 3~18 등 선택 타입에 필요한 정적 이미지 전체 제작, 실제 얼굴·시트·제품 참조 사용 | 각 슬롯의 파일·생성 기록·얼굴/제품 검수 |
| Flow | 리드당 5장면 스토리보드 한 번, 출력 x1 | UI 모델·길이·비용 캡처, 예약 ID, 원본 MP4 하나 |
| 편집 | 원본별 1초×5의 무자막 편집본을 만든 뒤 로컬 Remotion으로 자막 모드 적용 | 리드별 30fps/150프레임, 원문 데이터, 선택에 맞는 타이포/무자막 증거 |
| 조립 | 작업 사본의 모든 필요한 이미지·문구·브랜드·표를 채우고 리드 MP4 삽입 | 편집 가능한 전체 Figma 결과·렌더·프로토타입 재생 증빙 |
| QA | 전체 슬롯 누락/상품·얼굴 변형/문구 잔존/겹침/영상·자막 모드 검수 | 실제 결과에 연결된 QA 기록 |
| 출력 | 완성된 편집 가능한 Figma, 리드별 다운로드 MP4 두 개, 정적 이미지·미리보기 | 전체 산출물·해시·개별 다운로드 링크 |

스크립트가 계획을 생성했다고 실제 생성 단계가 완료되는 것은 아니다. 외부 생성과 Figma 편집은 Codex가 실제 도구로 실행한다. 공급자 도구는 런타임에서 탐색하고 해당 스킬을 적용한다. 자동화는 로그인된 PC와 실행 중인 Codex를 전제로 한다.

## 전체 정적 이미지와 카피

TYPE6의 현재 원고는 아래처럼 연결한다. TYPE1~7의 실제 구조는 `config/template-structure.json`과 [템플릿 연결 규칙](template-map.md)에서 확인한다. 번호가 여러 개 합쳐진 프레임이나 한 항목 안의 복수 이미지도 각각 기록하고 검수한다.

| 현재 TYPE6 항목 | 필요한 제작 | 편집 가능한 정보와 사실 기준 |
|---|---|---|
| 3~4 브랜드 소개·스토리 | 브랜드 콘셉트에 맞는 화보·제품 배경 이미지 | 정확한 브랜드명·슬로건·스토리; 확인되지 않은 업체 역사/실적 제외 |
| 5 사은품 | 실제 증정품이 확인된 경우에만 해당 상품 이미지 | 증정 조건; 사은품이 없으면 모듈 제외와 사유 기록 |
| 6 장점 비교 | 확인된 제품 구조·디테일을 보여주는 비교용 컷 | 실제 장점 카피; 수치/성능/경쟁 제품에 대한 허위 주장 제외 |
| 7 제품 랜딩 | 제품 전체를 보여주는 대표 이미지 | 제품명과 확인된 핵심 특징 |
| 8 다양한 활용도 | 실제 활용도 슬롯 수에 맞춘 착용 화보 여러 장 | 활용 상황 카피와 고정 모델/제품 검수 |
| 9~11 POINT1~3 | 홀·스트랩·챙 등 원본에서 확인한 특징별 디테일 | 근거가 있는 POINT 제목·설명 |
| 12 강조 카피 | 템플릿에 필요한 배경/제품 이미지 | 편집 가능한 강조 타이포 |
| 13 사용방법 | 확인한 사용 단계별 이미지와 배치 | 실제 조작 순서; 미확인 구조/동작을 생성해 사실로 안내하지 않음 |
| 14 POINT5 | 일상·활동 콘셉트 화보와 실제 슬롯별 컷 | 확인된 활용도와 창작 카피 구분 |
| 15 디테일뷰 | 원본 제품과 일치하는 확대·전체 디테일 컷 | 임의 로고/봉제/부품 추가 금지 |
| 16 제품사이즈·색상 | 실제 판매 색상별 제품 컷 | 확인된 치수·옵션·구조; 미제공 수치 생성 금지 |
| 17 QNA | 템플릿이 요구하는 보조 이미지가 있으면 해당 슬롯 제작 | 제품 근거에 맞는 질문·답변을 텍스트로 유지 |
| 18 제품정보 | 제품정보 표와 필요한 제품 이미지 배치 | 판매자가 확인한 사양; 소재/세탁법 등 미확인 정보 명시 |

각 실제 이미지 슬롯은 `job.sections[].assets[]`에 별도 파일과 프롬프트로 추적한다. 원고의 3~18을 한 장으로 대체하거나 활용도·색상·사용법 슬롯을 누락하지 않는다. 브랜드명·카피·QNA·치수·제품정보는 Figma에서 수정할 수 있게 텍스트·표로 조립한다. 사진에서 관찰한 구조, 판매자가 확인한 사실, 분위기를 위한 창작 카피를 분리한다. 캐릭터 시트와 표정 시트는 생성 참조이며 광고 슬롯에 그대로 넣는 이미지가 아니다.

착용 컷의 imagegen 입력에는 기준 얼굴·필요한 시트·원본 제품 사진을 실제로 첨부한다. 몽환적인 화보 표정이나 스타일 레퍼런스는 시선·표정·빛·분위기의 참고로만 사용하고 승인된 얼굴을 교체하지 않는다. 의상과 헤어스타일은 추가 컷별 승인 없이 제품·계절·콘셉트에 맞춰 설계하되 연속 장면에서는 유지한다. Flow에는 이미 검수한 생성 장면과 필요한 정체성/제품 참조를 리드당 최대 5개 안에서 선택한다.

## 영상 타이밍

| 원고 항목 | 시작 | 끝(미포함) | 프레임(0부터) |
|---|---:|---:|---|
| 1 | 0초 | 1초 | 0~29 |
| 2 | 1초 | 2초 | 30~59 |
| 3 | 2초 | 3초 | 60~89 |
| 4 | 3초 | 4초 | 90~119 |
| 5 | 4초 | 5초 | 120~149 |

리드메시지1과2 모두 이 구조로 제작한다. **리드당 생성 요청 한 번, 출력 x1**이다. 다섯 장면의 타임스탬프 스토리보드를 한 번 전달하며, 5초 생성이 지원되지 않으면 현재 UI의 지원 길이로 원본 하나를 만든다. 생성 모델의 컷 시각은 보장되지 않으므로 실제 결과를 보고 `media.py --source ... --edit-map ...`에 구간을 기록해 최종 1초씩 조립한다. 짧은 안전 구간은 edit-map의 `source_duration`으로 지정하고 그 밖의 프레임을 넣지 않는다. 제품 불일치·장면 누락은 편집 가능한 범위와 미완료 항목을 기록하며 장면별 다섯 생성으로 자동 전환하지 않는다. 입력 사진 없는 뒷면·내부를 사실처럼 창작하지 않는다.

영상 비율은 실제 슬롯의 보이는 영역을 기준으로 정한다. 프레임 바깥 레이어 크기를 생성 크기로 사용하지 않는다. 착용 화보·제품 회전·디테일을 중심으로 검수된 줌·슬로 연출을 사용한다. 실제 회전 소스가 없는 영상을 360도 촬영으로 표시하지 않는다.

생성 후 검수한 구간을 FFmpeg에서 `--style fullbleed-motion --caption-mode without-captions --caption-band 0`으로 편집한다. 이 깨끗한 5초 편집본을 로컬 Remotion에 넣어 저장한 자막 모드를 적용한다. **자막 있음은 Gmarket Sans Bold (`GmarketSansTTFBold.ttf`), 자막띠 0px, 검은 하단바 금지**다. 제품을 가리지 않는 여백에 포인트 키워드·보조문구를 움직이게 배치한다. 자막 없음은 글자·띠·텍스트 모션을 모두 생략한다. 축약 카피는 job의 `seconds[].overlay`에 문구와 사유를 남기고 원문 자막·JSON을 두 모드 모두 보존한다. 없는 제품 주장이나 효능을 추가하지 않는다. 실제 표시 자막과 원문 자막을 구분하고 각 카피가 해당 1초 구간에 있는지, 또는 무자막이 유지되는지 검수한다. 원본 오디오를 보존하며 새 음성/BGM을 자동 추가하지 않는다.

## 템플릿 적용

받은 공유 원본의 권한은 바꾸지 않는다. 최초1회 제공된 `.fig`를 사용자 계정의 편집 가능한 마스터 사본으로 가져온다. 그 마스터를 제품마다 다시 복제한다. 가져온 파일의 새로운 fileKey와 live ID를 `.local/connections.json`에 기록한다.

파일명과 페이지명에 TYPE7이 있어도 내부에 TYPE1~7 전체가 있다. 아이콘 페이지와 템플릿 페이지를 구분한다. 타입별 프레임 수, 별도 영상 그룹, 중복 이름, 한 프레임에 합쳐진 섹션을 실제 구조에서 확인한다.

템플릿 샘플의 사은품·후기·판매 수·별점·환불 약속은 자동 승계하지 않는다. 해당 사실이 없으면 복제본에서 그 모듈을 제외한다. 실측을 모르면 임의 치수를 넣지 않는다. 원고의 브랜드 이야기 역시 실제 업체 역사나 실적을 단정하지 않도록 검수한다.

템플릿의 이미지 슬롯 수와 원고 내용이 다르면 복제본 레이아웃을 조절한다. 예: TYPE6 활용 장면 슬롯5개/원고6장면, 색상 슬롯4개/실제2색. 빈 슬롯을 가짜 색상으로 채우지 않는다. 수정 후 제품 이미지 크롭·텍스트 높이·다음 섹션과 간격을 확인한다.

전체 작업 사본에는 선택 타입의 리드 1·2 및 나머지 모든 필요한 이미지·카피를 배치한다. 원고 항목별 이미지·문구·브랜드·QNA·사양 표가 채워졌는지 live ID와 함께 기록한다. 사실에 따라 제외한 모듈은 사유를 남긴다. 받은 원본이나 작업용 마스터에 결과를 덮어쓰지 않는다.

MP4는 [Figma 미디어 실행서](figma-media.md)의 검증된 네이티브 **File → Place image/video** 경로로 가져온다. 실제 생성된 VIDEO fill 노드를 작업 사본으로 옮겨 배치한다. 현재 연결의 `upload_assets`는 이미지용이며 `use_figma`로 VIDEO fill을 직접 지정하는 방식은 지원되지 않았다. 네이티브 MP4 삽입이 성공한 사본에서는 GIF 대체본을 숨기고 영상 위의 포스터·대기 문구를 제거한다.

프로토타입에서 두 리드의 실제 `<video>` 길이·크기·재생 상태와 시간 진행을 확인하고, 다른 시점의 스크린샷으로 제품·자막·배치를 검수한다. 정지 렌더만으로 영상 재생을 통과시키지 않는다. 실제 메뉴·권한·재생 결과는 작업마다 다시 확인하되 이미 검증된 삽입 경로부터 사용한다.

## 출력과 완료

납품 폴더에는 **필요한 정적 이미지·카피·브랜드·제품정보를 모두 채운 편집 가능한 Figma 작업 사본 링크**와 **각각 다운로드할 최종 리드1·리드2 MP4 두 개**를 둔다. 순서가 정해진 정적 이미지, 재생되는 preview.html, qa.json, delivery-manifest.json도 제공한다. 두 자막 모드 모두 원문 SRT/JSON 데이터를 보존하며 자막 있음에는 실제 표시 자막 데이터도 포함한다. 자막 없음의 납품 목록에 표시 자막이 들어 있다고 기록하지 않는다. Figma 링크만으로 영상 납품을 대신하지 않는다. 템플릿 원본 폭은 780px이나 실제 파일에서 재확인한다. 세로 이미지는 섹션별로 출력해 순서를 기록한다.

정적 PNG/JPG에는 동영상이 재생되지 않는다. 해당 환경에서 네이티브 MP4 삽입이 실제로 막혔을 때만 GIF 대체를 검토하고, 실제 재생이 확인된 형식을 기록한다. MP4가 들어간 Figma 편집본 요구가 남아 있으면 포스터·GIF·외부 MP4·HTML과 구분해 표시한다. 쿠팡 업로드 형식·용량·동영상 제공 방식은 실제 업로드 작업 시 공식 판매자 UI에서 확인한다. 임의의 지원 규격을 하드코딩하지 않는다.

최종 QA는 파일 존재 확인 외에 **전체 이미지 슬롯의 제작·배치, 제품 구조/색상, 기준 얼굴, 연속 장면의 의상/헤어스타일, 초별 영상과 자막 선택, 실제 Figma의 잘림/겹침/샘플 문구 제거**를 포함한다. 영상의 실제 재생과 개별 다운로드 MP4도 확인한다. 실제 검수 결과를 파일 해시와 연결해 저장한다. 원고의 필요한 모든 항목·Figma 배치·납품 검수가 끝나야 전체 `complete`로 표시한다.

리드 2개만 제작한 경우 모든 샘플 검증을 통과해도 `sample_verified`, `page_complete:false`다. 이동 가능한 샘플 HTML 묶음은 `scripts/sample_delivery.py`로 만들며 전체 납품용 `delivery-manifest.json`과 구분한다. Figma 영상 재생 확인은 After Effects 실행 증거가 아니다. AE JSX 준비·FFmpeg MP4·실제 AE 렌더의 상태를 각각 기록한다.

워크프로세스 설정·고정 모델/시트 제작 요청은 그 설정과 참조물 제작으로 완료한다. 이 요청만으로 상세페이지 본문 3~18이나 전체 Figma 결과를 제작했다고 보고하지 않는다. 이후 전체 제작 요청에서 저장한 참조·계획·검수된 원본을 재사용한다.

## 재개와 예외

새 계획은 `single-source-v2`가 기본이다. Flow 제출 전 `generation-start`로 리드당 요청 한 자리를 예약하고 실제 UI의 모델·길이·x1·표시 비용과 스크린샷 해시를 저장한다. 예약한 요청의 결과가 불명확하면 기존 결과부터 확인하며 다시 제출하지 않는다. 재시작한 계획이나 전체 페이지 재개에서도 요청 슬롯을 재사용한다. `flow-tasks.json`은 계획일 뿐 재제출 권한이 아니므로 매번 `state.json`을 먼저 확인한다.

완료된 생성물은 해시와 입력 변경 여부를 확인해 재사용한다. 원고가 바뀌면 로컬 편집·자막·슬롯을 먼저 보정한다. 정적 이미지의 확인된 실패 재시도와 영상 요청을 구분하며 **영상은 자동 재요청하지 않는다**. 새 생성이 필요한 경우 사유를 설명하고 별도 지시를 받는다. 이전 `legacy-five-source-v1` 파일·QA는 역사로 보존하며 새로운 v2 결과로 덮어쓰지 않는다.

로그인 만료, Figma 편집권한, 필수 사실 누락, 정확한 이미지 모델을 실행하지 못하는 경우는 원인과 필요한 조치만 알린다. 사용자가 해결하는 동안 독립 작업은 진행한다. 매 컷마다 승인을 받거나 수동 작업을 요구하지 않는다.
