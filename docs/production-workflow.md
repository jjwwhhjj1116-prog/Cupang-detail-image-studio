# 4단계 이후 자동 제작 절차

## 인수 경계

사용자는 하디 고정 채팅에서 1) 시작, 2) 제품 사진 제공, 3) 타입 선택, 4) 타입별 최종 프롬프트 수령을 한다. Codex가 원고와 사진을 전달받는 시점부터 자동 제작이 시작된다. 다른 ChatGPT 채팅을 상시 감시하거나 사용자의 메시지를 자동 전송하는 기능은 포함하지 않는다. 같은 자료를 반복해서 입력하게 하지 않는다.

작업 시작에 필요한 입력은 **브랜드(와이홉/유앤채), TYPE1~7, 최종 프롬프트, 원본 제품 사진**이다. 프롬프트에서 타입을 확실히 알 수 있으면 다시 묻지 않는다. 소재·세탁법·치수·구성품·실제 옵션·사은품 등은 판매자가 확인한 값만 사용한다. 실제 로고가 없으면 정확한 브랜드명을 텍스트로 넣고 원본 디자인 스타일을 따른다.

## 자동 실행

| 단계 | Codex가 할 일 | 완료 증거 |
|---|---|---|
| 인수 | 원고·제품사진 보존, 작업 ID와 상태 생성 | 원본 파일, job.json |
| 사실 검수 | 사진 관찰/판매자 확인/창작 카피를 구분 | 근거·누락 목록 |
| 슬롯 연결 | 실제 Figma 노드 확인, 선택 타입 복제 | live ID 및 복제 ID 매핑 |
| 컷 설계 | 슬롯별 목적·참조사진·구도·배경·크롭 설계 | 이미지 및 영상 작업 목록 |
| 이미지 | 정적 슬롯 제작, 리드당 참조 1~5개 선택·재사용 | 파일·생성 기록·검수 |
| Flow | 리드당 5장면 스토리보드 한 번, 출력 x1 | UI 모델·길이·비용 캡처, 예약 ID, 원본 MP4 하나 |
| 편집 | 한 원본의 검수 구간을 1초×5로 편집, 영상 위 타이포 합성 | 30fps/150프레임, 표시/원문 SRT, ASS·글꼴 증거 |
| 조립 | Figma 이미지·문구·브랜드·표 배치, 네이티브 UI로 최종 MP4 삽입 | 편집본·렌더·프로토타입 재생 증빙 |
| QA | 상품 변형/문구 잔존/겹침/영상·자막 검수 및 보정 | 실제 결과에 연결된 QA 기록 |
| 출력 | 순서별 상세 이미지·영상·미리보기·납품 목록 | 전체 산출물·해시 |

스크립트가 계획을 생성했다고 실제 생성 단계가 완료되는 것은 아니다. 외부 생성과 Figma 편집은 Codex가 실제 도구로 실행한다. 공급자 도구는 런타임에서 탐색하고 해당 스킬을 적용한다. 자동화는 로그인된 PC와 실행 중인 Codex를 전제로 한다.

## 영상 타이밍

| 원고 항목 | 시작 | 끝(미포함) | 프레임(0부터) |
|---|---:|---:|---|
| 1 | 0초 | 1초 | 0~29 |
| 2 | 1초 | 2초 | 30~59 |
| 3 | 2초 | 3초 | 60~89 |
| 4 | 3초 | 4초 | 90~119 |
| 5 | 4초 | 5초 | 120~149 |

리드메시지1과2 모두 이 구조로 제작한다. **리드당 생성 요청 한 번, 출력 x1**이다. 다섯 장면의 타임스탬프 스토리보드를 한 번 전달하며, 5초 생성이 지원되지 않으면 현재 UI의 지원 길이로 원본 하나를 만든다. 생성 모델의 컷 시각은 보장되지 않으므로 실제 결과를 보고 `media.py --source ... --edit-map ...`에 구간을 기록해 최종 1초씩 조립한다. 짧은 안전 구간은 edit-map의 `source_duration`으로 지정하고 그 밖의 프레임을 넣지 않는다. 제품 불일치·장면 누락은 편집 가능한 범위와 미완료 항목을 기록하며 장면별 다섯 생성으로 자동 전환하지 않는다. 입력 사진 없는 뒷면·내부를 사실처럼 창작하지 않는다.

영상 비율은 실제 슬롯의 보이는 영역을 기준으로 정한다. 프레임 바깥 레이어 크기를 생성 크기로 사용하지 않는다. 착용 화보·제품 회전·디테일을 중심으로 검수된 줌·슬로 연출을 사용한다. 실제 회전 소스가 없는 영상을 360도 촬영으로 표시하지 않는다.

타이포는 생성 후 `fullbleed-motion`으로 합성한다. **Gmarket Sans Bold (`GmarketSansTTFBold.ttf`), 자막띠 0px, 검은 하단바 금지**다. 제품을 가리지 않는 여백에 키워드·보조문구를 배치한다. 축약 카피는 job의 `seconds[].overlay`에 문구와 사유를 남기고 원문 자막·JSON을 보존한다. 없는 제품 주장이나 효능을 추가하지 않는다. 실제 표시 자막과 원문 자막을 구분하고 각 카피가 해당 1초 구간에 있는지 검수한다. 원본 오디오를 보존하며 새 음성/BGM을 자동 추가하지 않는다.

## 템플릿 적용

받은 공유 원본의 권한은 바꾸지 않는다. 최초1회 제공된 `.fig`를 사용자 계정의 편집 가능한 마스터 사본으로 가져온다. 그 마스터를 제품마다 다시 복제한다. 가져온 파일의 새로운 fileKey와 live ID를 `.local/connections.json`에 기록한다.

파일명과 페이지명에 TYPE7이 있어도 내부에 TYPE1~7 전체가 있다. 아이콘 페이지와 템플릿 페이지를 구분한다. 타입별 프레임 수, 별도 영상 그룹, 중복 이름, 한 프레임에 합쳐진 섹션을 실제 구조에서 확인한다.

템플릿 샘플의 사은품·후기·판매 수·별점·환불 약속은 자동 승계하지 않는다. 해당 사실이 없으면 복제본에서 그 모듈을 제외한다. 실측을 모르면 임의 치수를 넣지 않는다. 원고의 브랜드 이야기 역시 실제 업체 역사나 실적을 단정하지 않도록 검수한다.

템플릿의 이미지 슬롯 수와 원고 내용이 다르면 복제본 레이아웃을 조절한다. 예: TYPE6 활용 장면 슬롯5개/원고6장면, 색상 슬롯4개/실제2색. 빈 슬롯을 가짜 색상으로 채우지 않는다. 수정 후 제품 이미지 크롭·텍스트 높이·다음 섹션과 간격을 확인한다.

MP4는 [Figma 미디어 실행서](figma-media.md)의 검증된 네이티브 **File → Place image/video** 경로로 가져온다. 실제 생성된 VIDEO fill 노드를 작업 사본으로 옮겨 배치한다. 현재 연결의 `upload_assets`는 이미지용이며 `use_figma`로 VIDEO fill을 직접 지정하는 방식은 지원되지 않았다. 네이티브 MP4 삽입이 성공한 사본에서는 GIF 대체본을 숨기고 영상 위의 포스터·대기 문구를 제거한다.

프로토타입에서 두 리드의 실제 `<video>` 길이·크기·재생 상태와 시간 진행을 확인하고, 다른 시점의 스크린샷으로 제품·자막·배치를 검수한다. 정지 렌더만으로 영상 재생을 통과시키지 않는다. 실제 메뉴·권한·재생 결과는 작업마다 다시 확인하되 이미 검증된 삽입 경로부터 사용한다.

## 출력과 완료

납품 폴더에는 편집 가능한 Figma 링크, 순서가 정해진 정적 이미지, **다운로드 가능한 최종 리드1·2 MP4 두 개**, 표시/원문 SRT·ASS 자막, 재생되는 preview.html, qa.json, delivery-manifest.json을 둔다. Figma 링크만으로 영상 납품을 대신하지 않는다. 템플릿 원본 폭은 780px이나 실제 파일에서 재확인한다. 세로 이미지는 섹션별로 출력해 순서를 기록한다.

정적 PNG/JPG에는 동영상이 재생되지 않는다. 해당 환경에서 네이티브 MP4 삽입이 실제로 막혔을 때만 GIF 대체를 검토하고, 실제 재생이 확인된 형식을 기록한다. MP4가 들어간 Figma 편집본 요구가 남아 있으면 포스터·GIF·외부 MP4·HTML과 구분해 표시한다. 쿠팡 업로드 형식·용량·동영상 제공 방식은 실제 업로드 작업 시 공식 판매자 UI에서 확인한다. 임의의 지원 규격을 하드코딩하지 않는다.

최종 QA는 파일 존재 확인 외에 제품 구조/색상 보존, 5개 동작과 자막의 일치, 실제 Figma 렌더의 잘림/겹침/샘플 문구 제거를 포함한다. 실제 검수 결과를 파일 해시와 연결해 저장한다. 준비 문서만으로 완료 표시하지 않는다.

리드 2개만 제작한 경우 모든 샘플 검증을 통과해도 `sample_verified`, `page_complete:false`다. 이동 가능한 샘플 HTML 묶음은 `scripts/sample_delivery.py`로 만들며 전체 납품용 `delivery-manifest.json`과 구분한다. Figma 영상 재생 확인은 After Effects 실행 증거가 아니다. AE JSX 준비·FFmpeg MP4·실제 AE 렌더의 상태를 각각 기록한다.

## 재개와 예외

새 계획은 `single-source-v2`가 기본이다. Flow 제출 전 `generation-start`로 리드당 요청 한 자리를 예약하고 실제 UI의 모델·길이·x1·표시 비용과 스크린샷 해시를 저장한다. 예약한 요청의 결과가 불명확하면 기존 결과부터 확인하며 다시 제출하지 않는다. 재시작한 계획이나 전체 페이지 재개에서도 요청 슬롯을 재사용한다. `flow-tasks.json`은 계획일 뿐 재제출 권한이 아니므로 매번 `state.json`을 먼저 확인한다.

완료된 생성물은 해시와 입력 변경 여부를 확인해 재사용한다. 원고가 바뀌면 로컬 편집·자막·슬롯을 먼저 보정한다. 정적 이미지의 확인된 실패 재시도와 영상 요청을 구분하며 **영상은 자동 재요청하지 않는다**. 새 생성이 필요한 경우 사유를 설명하고 별도 지시를 받는다. 이전 `legacy-five-source-v1` 파일·QA는 역사로 보존하며 새로운 v2 결과로 덮어쓰지 않는다.

로그인 만료, Figma 편집권한, 필수 사실 누락, 정확한 이미지 모델을 실행하지 못하는 경우는 원인과 필요한 조치만 알린다. 사용자가 해결하는 동안 독립 작업은 진행한다. 매 컷마다 승인을 받거나 수동 작업을 요구하지 않는다.
